# V1 · 최소 실행 그래프 (walking skeleton)

## 무엇을 만들었나
`StateGraph` → `compile()` → `invoke()`가 도는 가장 작은 엔진. 선형 그래프 `START→a→b→END`가 상태를 변환한다.

- **상태 = 평범한 객체.** 노드가 돌려준 부분 상태를 `{...state, ...update}`로 얕게 병합.
- **노드 = `(state) => Partial<state>`** (async 허용).
- **실행 = 순차 edge-following.** START의 아웃엣지에서 시작해, 노드 실행 → 병합 → 다음 엣지, END에서 멈춤.
- **`compile()`은 거의 no-op.** 지금은 검증 + 노드/엣지 맵 복사뿐. (나중에 여기서 "Pregel로 낮추는" 컴파일이 된다 — V7)

## langgraph의 무엇에 해당하나
`graph/state.py`의 **사용자 API 표면**(add_node / add_edge / compile / invoke)만. 내부 메커니즘(채널·PregelNode·superstep)은 하나도 없음.

## 처음 등장한 개념
- **상수 `START`/`END`** (`src/constants.ts`): 가상 진입/종료 노드. dunder로 사용자 이름과 충돌 회피. → 이게 "필요해서 태어난" 첫 상수.

## 이 단계가 드러낸 벽 (다음 단계의 동기)
1. **상태 병합이 순진한 덮어쓰기.** 키별로 "어떻게 합칠지" 규칙이 없다. 저장/읽기/스냅샷도 제각각.
   → **V2: 채널**로 상태를 감싸 통일된 인터페이스(get/update/checkpoint)를 준다. 여기서 `MISSING`("아직 안 써짐")이 필요해진다.
2. **같은 키에 두 번 쓰면?** 지금은 그냥 마지막 값이 이김. 누적(리스트 append 등)이 불가.
   → **V3: 리듀서 채널**.
3. **아웃엣지 1개·순차 실행.** 분기·병렬·팬인이 구조적으로 불가.
   → **V4: superstep(BSP)**, **V5: 조건부 엣지**.

## 설계 메모
- **async를 처음부터.** V4에서 태스크를 동시에 실행할 것이므로 노드 반환을 `Promise` 허용으로 열어둠(`await node(state)`).
- **재귀 한도(100) 임시 가드.** 선형이라 사실상 안 걸리지만, 루프가 생기는 V5를 대비한 자리표시. V4에서 제대로.
- **빈 계층 디렉터리 제거.** `src/{channels,pregel,...}/`를 미리 만들지 않는다 — 구조는 필요할 때 생긴다(진화식 원칙).
