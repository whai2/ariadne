# F4.3 · 선택 기계 — 그리고 그 기계가 내놓은 **뜻밖의 답**

## 왜 이 커밋이 생겼나

F4.2가 후보를 셋 만들어 놓고 이 한 줄로 골랐다.

```ts
.filter((f) => f.level === "preference")
```

**F4.0 실험 결과를 코드에 박은 것**이고, 기계는 아무것도 안 배운 상태였다. 그리고 그 실험은
**한 과제·한 모델·한 문장**에서 쟀다 — 다른 에이전트에도 통한다는 보장이 없었다.

이 커밋이 그 하드코딩을 걷어낸다. 공고화(F4.2)가 **변이**를 만들고, 여기가 **선택**을 한다.

## 어떻게 — 네 가지

### 1. 한 턴에 **하나만** 시험한다

```ts
chooseFact(facts)   // 시행 적은 것 → 강도 높은 것 → id
```

셋을 동시에 주입하면 행동이 바뀌어도 **어느 게 바꿨는지 모른다.** 귀속이 안 되는 순간
이건 선택 기계가 아니라 그냥 프롬프트 덧붙이기다.

시행 적은 것을 먼저 고르는 게 라운드로빈이고, 그래야 초반에 운 좋게 이긴 후보가 나머지를
굶기지 못한다. 탐색과 활용의 가장 값싼 절충이다 — 통계적 밴딧은 이 단계 밖이다.

### 2. 판정은 **행동**을 본다

| 그 턴에 일어난 일 | 판정 |
|---|---|
| 대상 툴을 그냥 불렀다 | `decay` — 사실이 못 막았다 |
| 대상 툴을 안 불렀다 | `reinforce` |
| 불렀는데 승인 게이트가 멈춰 세웠다 | `neutral` — **게이트의 공이지 기억의 공이 아니다** |

세 번째 줄이 없으면 **게이트가 잘 막아준 걸 기억의 성적으로 착각한다.**

### 3. 어휘 중첩은 **안 쓴다**

처음 후보였던 "주입한 문장이 답에 겹치면 +1"은 폐기했다.

```
"write_note를 쓸까요?"    ← 성공인데 겹침
"write_note 했습니다"      ← 실패인데 겹침
```

**성공과 실패에 같은 점수를 주는 지표는 지표가 아니다.**

### 4. 점수는 캐시하지 않는다

`facts`에 `strength` 컬럼을 두지 않고 `injections`를 매번 집계한다. 숫자만 남기면
**"왜 이 사실이 이겼나"의 근거가 사라진다.** 시행 하나하나가 행으로 남아야 되짚을 수 있다.

그리고 판정이 `undefined`면(run이 던진 턴) **행을 지운다.** 모르는 걸 0점으로 기록하면
그건 관찰이 아니라 잡음이다.

## 실측 — 예상한 결과가 **안 나왔다**

이 커밋의 검증 기준은 이거였다: **사건형 후보가 스스로 도태되는가.** F4.0이 답을 이미
알고 있으니(사건 서술은 효과 0), 기계가 거기 도달하면 도는 것이라고 봤다.

스튜디오에서 `mcp` 에이전트로 돌린 결과:

```
기준선 (기억 없음, 6회)         →  즉시 툴 호출 6/6
후보 주입 (라운드로빈, 6회)      →  즉시 툴 호출 0/6

성적표
  [episodic  ] 시행 2  강도 +2
  [preference] 시행 2  강도 +2
  [rule      ] 시행 2  강도 +2
```

**셋이 동률이다. 사건형이 안 죽었다.**

### 감도 문제는 아니다

첫 의심은 "또 천장 효과 아닌가"였다(F4.0의 1차 설계가 그걸로 무효였다). 그래서 기준선을 쟀다.

**기준선 6/6 vs 주입 0/6.** 여유는 충분했다. 측정이 무딘 게 아니라 **정말로 셋 다 먹혔다.**

### 그럼 F4.0은?

F4.0에서 사건 서술은 6/6 즉시 호출이었다(효과 0). 여기선 0/6이다. 같은 종류의 문장인데
결과가 정반대다. 차이가 셋 있고, 어느 것 때문인지는 **아직 모른다.**

| | F4.0 | 여기 |
|---|---|---|
| 툴 | `write_file` (파일을 실제로 바꿈) | `write_note` (데모, 메모리에만) |
| system | 문장을 **맨몸으로** 붙임 | **`[기억한 것]` 블록**으로 감쌈 |
| 에이전트 | 파일 비서 | 날씨·단어수·메모 비서 |


**두 번째가 가장 의심스럽다.** F4.2의 `composeSystem`이 `[기억한 것]`이라는 **틀**을 새로
만들었는데, F4.0은 그 틀 없이 쟀다. 틀 자체가 "이건 기억이다"라는 신호를 줘서 약한 문장까지
살렸을 수 있다. **실험과 구현 사이에 내가 끼워 넣은 교란 변수**이고, 명시적으로 적어둔다.

## 그래서 이 커밋은 성공인가 실패인가

**둘 다 아니다. 기계는 돌았고, 답이 예상과 달랐다.**

- **기계는 돈다.** 라운드로빈이 셋에 정확히 2회씩 나눠줬고, 판정이 행으로 남았고, 순위가
  집계된다. 산수는 단위 테스트가 지킨다.
- **하드코딩을 걷어낸 게 옳았다.** 이번 결과가 그 증거다 — `preference`만 남겼으면
  **이 에이전트에선 똑같이 잘 듣는 후보 둘을 근거 없이 버렸을** 것이다.
- **다만 이 단계의 검증 기준은 재현되지 않았다.** "사건형이 도태된다"는 예측은 이 에이전트에서
  틀렸다.

노트 26(F3.3)에 이어 **두 번째로 사전 예측이 빗나갔다.** 그때는 우리 설계가 예상보다 나았고,
이번엔 실험의 일반화가 예상보다 좁았다. 둘 다 **먼저 재봤기 때문에** 알았다.

## 검증

- `bun run --filter '@ariadne/memory' example:loop` — **자격증명 0 · 네트워크 0.**
  거부 2회 → 후보 셋 → 12턴 라운드로빈 → 성적표. **단, 이 데모는 "사건형이 약하다"를 코드로
  가정하고 돌린다** — 산수를 보여주는 것이지 증거가 아니다.
- 테스트 +18 (memory 29 → **46**, studio 64 → **68**): `chooseFact`의 순서 규칙 · **level이
  순위에 안 쓰인다** · `judge`의 세 갈래(특히 `neutral`) · 무관한 턴도 시행으로 셈 ·
  `undefined` 판정이 행을 지움 · 도태돼도 행은 남음 · `injections`의 CHECK 제약 ·
  스튜디오가 성적까지 실어 보냄.
- **손으로 (진짜 모델, API 키 0):** 위 실측. 기준선 6/6 → 주입 0/6, 셋 동률.
- `bun run verify` 그린: **385 pass / 4 skip / 0 fail** (core 81 · **memory 46** · tools 28 ·
  mcp 37 · model 105 · agent 20 · studio **68**). **memory·studio 밖 다섯 패키지 무수정.**

## 안 한 것 (정직)

- **감쇠(시간에 따른)** — 안 쓰이면 점수가 깎이는 규칙이 없다. 시행이 곧 점수라 방치된 사실은
  그냥 그대로 있다.
- **삭제** — 도태된 사실도 안 지운다. **왜 졌는지가 근거**라서 남긴다. 수백 개가 되면 그때 판단.
- **탐색/활용 균형** — 라운드로빈이 전부다. 이긴 후보를 더 자주 쓰지 않는다(그러면 귀속이
  흐려진다). 밴딧은 후보가 훨씬 많아질 때 얘기다.
- **에이전트 간 공유** — 성적은 에이전트별로만 쌓인다.
- **체크포인터** — F4.4.

## 벽 → 다음

**판정이 이분법이라 셋을 못 가른다.**

지금 신호는 "대상 툴을 불렀나" 하나뿐이다. 셋 다 안 부르게 만들면 **셋 다 만점**이고,
라운드로빈이 영원히 돌 뿐 순위가 안 생긴다. 실측이 정확히 그 상태다(전부 +2).

더 가르려면 **더 미세한 신호**가 필요하다. 후보 셋:
- 사람이 결국 **승인했나** — 잘 물어본 기억이면 승인률이 높아야 한다
- 몇 턴 만에 끝났나 — 좋은 기억은 왕복을 줄인다
- 토큰 — 짧은 문장이 같은 효과면 그게 낫다

그리고 이번에 드러난 교란 변수(`[기억한 것]` 틀)도 재봐야 한다. **틀만 남기고 문장을 빼면
어떻게 되나** — 그게 다음 실험이다.
