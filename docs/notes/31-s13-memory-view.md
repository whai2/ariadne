# S13 · 메모리 뷰 — 행동이 바뀌는데 **원인이 안 보이던** 자리

## 왜 이 커밋이 생겼나

F4.2가 목표 장면을 달성했다 — 거부를 두 번 하면 세 번째 턴에 모델이 툴을 바로 안 부르고 먼저
묻는다. 그런데 **화면에서 보면 그냥 모델이 갑자기 다르게 굴었다.** 사실은 `system`에 접혀 들어가
모델만 보고, 쌓인 기억은 `GET /api/memory`가 내려주는데 **그걸 읽는 화면이 하나도 없었다**
(`web/src`에 `memory`라는 단어가 한 번도 안 나왔다).

관찰 도구에 관찰 구멍이 있었던 셈이다. 도착점 한 줄: **기억이 행동을 바꾸는 것을 눈으로 본다.**

## 관찰이 두 종류라는 걸 먼저 갈랐다

붙일 것이 하나가 아니었다. 질문이 둘이고 **답이 오는 자리도 다르다.**

| 질문 | 답이 있는 곳 | 화면의 자리 |
|---|---|---|
| **이번 턴에** 어느 기억을 썼나 | 어디에도 없었다 → 새로 실었다 | 대화 바로 위 (원인) |
| **지금까지** 무엇이 쌓였나 | `GET /api/memory` (이미 있었다) | 아래 전체 폭 (누적) |

둘을 한 패널에 합치지 않은 이유가 여기 있다. 아래 표는 *역사*고, 띠는 *이번 run의 전제*다.
전제는 대화 옆에 있어야 읽힌다 — 모델이 왜 저렇게 답했는지를 바로 위에서 설명하기 때문이다.

## 발견 · 주입은 **응답에만** 실을 수 있었다

"이번 턴에 어느 사실을 썼나"는 이미 `injections` 테이블에 `(fact_id, episode_id)`로 남는다.
그런데 그걸 **에피소드로 되짚는 조회가 없다.** 그리고 만들 이유도 없었다 — 클라이언트는 방금
자기가 부른 턴의 결과를 묻는 것이지, 과거의 어느 run을 조회하는 게 아니다.

그래서 **응답에 필드 하나가 늘었다.** S12의 `pending`과 정확히 같은 모양이다:

```ts
export interface AgentReply {
  messages: BaseMessage[];
  steps: StepUpdate<MessagesState>[];
  pending: ToolCall[];
  injected?: Injected;   // ← 이번 커밋
}
```

S12 노트가 `pending`에 대해 적은 문장이 그대로 적용된다 — **안쪽에선 부재로, 경계 밖에선 존재로
표현되는 같은 사실.** 주입은 엔진 안에서 그냥 `system` 문자열의 일부이고(F4.2: "새 노드도 새 채널도
아니라 문자열 합치기"), 경계를 넘는 순간에만 이름을 가진 것이 된다.

그리고 **사실이 없으면 키를 아예 안 만든다**(F2.1이 `toolCalls`에 세운 규칙). 새 엔드포인트는
하나도 안 생겼다 — `/api/memory`는 한 글자도 안 바뀌었고 라우터의 형제 `if`는 여전히 넷이다.

## 곁다리로 `finished` 플래그가 사라졌다

주입 판정(`judge`)이 원래 `finally` **안**에 있었다. 응답에도 그 값을 실어야 하니 성공 경로로
끌어올렸는데, 그러자 플래그가 필요 없어졌다.

```ts
// 전 — 판정이 finally에서 나고, "끝까지 돌았나"를 플래그로 들고 있어야 했다
let finished = false;
…
finished = true;
return { messages: produced, steps, pending };
} finally {
  memory.endInjection(injection, finished ? judge(fact.target, produced, pending) : undefined);
}

// 후 — 판정을 성공 경로에서 내니, "못 냈다"가 변수의 부재로 그냥 표현된다
let outcome: InjectionOutcome | undefined;
…
if (fact !== undefined) outcome = judge(fact.target, produced, pending);
return { …, ...(fact === undefined ? {} : { injected: { fact, outcome: outcome ?? null } }) };
} finally {
  memory.endInjection(injection, outcome);
}
```

`undefined`가 **"아직 판정 전"**이라는 뜻은 스키마가 이미 정해둔 것이다(`InjectionRow.outcome`의
`NULL`). 플래그는 그 뜻을 한 번 더 적고 있었을 뿐이다. **DB에 쓰는 값과 응답에 싣는 값이 같은
변수**가 됐으니 둘이 어긋날 자리도 없어졌다 — 테스트가 그걸 못박는다.

## 판단 · 띠의 숫자는 **주입 직전**의 성적이다

실측 화면에서 바로 걸렸다. 띠는 `0 (0회)`인데 바로 아래 표는 `1 / +1`이었다.

틀린 게 아니라 **시점이 다르다.** 응답의 `fact`는 턴 시작에 읽은 것(그때의 성적으로 골랐으니까)이고,
표는 턴이 끝난 뒤 다시 읽은 것이다. 한 칸 앞서 있는 게 맞다. 그래서 숫자를 맞추는 대신 **라벨에
시점을 적었다** — `주입 전 성적`. 이번 턴의 기여분은 바로 아랫줄 `판정`이 말한다.

이걸 억지로 맞추면(응답을 턴 끝에 다시 읽어 싣기) 화면은 깔끔해지지만 **무엇으로 골랐는지가
사라진다.** 선택의 근거가 관찰의 대상인 단계에서 그건 손해다.

## 층을 셋으로 나눠 그린 이유

`Memory.tsx`가 한 표가 아니라 세 블록인 건 **쌓이는 조건이 다르기 때문**이다. F4.1이 테이블을
가른 그 이유가 화면에도 그대로 올라온다.

| 블록 | 언제 쌓이나 | 화면이 말하는 것 |
|---|---|---|
| 사실 (`facts`) | 한 툴에 거부 ≥2 **그리고** 거부 > 승인 | 모델에게 실제로 가는 문장 + 성적 |
| 가치 신호 (`value_events`) | 사람이 버튼을 **실제로 눌렀을 때** | 해석이 안 들어간 날것의 결정 |
| 에피소드 (`episodes`) | 매 run **무조건** | `paused`가 완결된 run으로 보인다 |

사실 표에 **`origin`(`"deny 8 / allow 6"`)과 `trials`/`strength`를 같이 놓은 게 이 패널의 요점**이다.
왜 생겼는지와 얼마나 잘 듣는지가 한 줄에 있어야 F4.3의 벽("판정이 이분법이라 셋을 못 가른다")이
숫자로 보인다. 실측 화면에서 정확히 그게 보였다 — 사건형과 선호형이 나란히 `+1`.

## 검증

- **진짜 모델 · API 키 0**(claude-code/sonnet). 거부를 쌓아두고 "메모 저장해줘"를 보내면:
  ```
  injected.fact  : "사용자는 write_note이(가) 확인 없이 실행되는 것을 원하지 않는다."
  injected.outcome: "reinforce"
  steps          : [["model"]]     ← 툴 노드에 아예 안 갔다
  ```
  F4.2의 목표 장면이 이제 **응답 한 덩어리로 관찰된다.**
- **헤드리스 크롬으로 실제 렌더 + 클릭까지.** 패널 세 블록, 주입 띠, 판정 줄(`강화 · 대상 툴을
  안 불렀다`), 사실 표에서 주입된 행 강조까지 확인.
- 테스트 +3 (studio 31 → **34**): 응답이 시험한 사실 하나를 싣고 그 `fact.id`가 DB의 사실 중
  하나이며 시행이 1 늘었다 · 사실이 없으면 `injected` **키 자체가 없다** · 스토어가 없어도 마찬가지.
- `bun run verify` 그린: **351 pass / 3 skip / 0 fail** (core 81 · memory 46 · tools 28 · mcp 37 ·
  model 105 · agent 20 · studio **34**). **스튜디오 밖 여섯 패키지 무수정.**

## 안 한 것 (정직)

- **`injections` 낱개 행을 안 보여준다.** 표에 `trials`/`strength`(집계)만 올렸다. F4.3이 "숫자만
  남기면 왜 이겼는지가 사라진다"며 행을 보존했는데, **화면은 아직 그 행을 안 읽는다.** 후보를
  가르는 작업(F4.3의 벽)을 할 때 필요해지면 그때 연다.
- **새로고침이 수동이 아니다** — 턴이 끝날 때마다 `/api/memory`를 다시 읽는다. 폴링도 스트리밍도
  없으니 다른 탭에서 쌓인 건 안 보인다.
- **사용자 축이 여전히 없다.** 격리 키가 `agent` 하나라 여러 사람이 쓰면 A의 거부가 B의 프롬프트에
  실린다. 패널에 그 사실을 **문장으로 적어뒀다** — 고치는 건 세션이 들어올 때(F4.4)다.
- 기억의 수동 편집·삭제 없음. 화면은 **읽기 전용**이다(사람이 손으로 고치기 시작하면 성적이
  무엇의 결과인지 알 수 없게 된다).

## 벽 → 다음

화면에서 읽을 수 있다. 다음은 그 동률을 가르는 일이고, 순서는 앞서 정리한 대로다 —

그 답에 따라 판정 신호를 늘린다.
