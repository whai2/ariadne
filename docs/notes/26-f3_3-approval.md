# F3.3 · 승인 게이트 — 인터럽트 없이 멈추고, 체크포인터 없이 재개한다

## 왜 이 커밋이 생겼나

F3.2/S11이 남긴 벽이 구체적이었다. 스튜디오의 `filesystem` 에이전트는 **남이 만든 서버**에서
`edit_file`·`write_file`을 받아 든다. 사람이 그 실행을 막을 자리가 없어서, S11은 열어주는 폴더를
`mcp-sample/` 하나로 좁혔다 — 노트 25가 적었듯 **정책이 아니라 회피**다.

그리고 노트 24가 이 단계를 미룬 이유가 있었다:

> 승인 게이트는 중단/재개(= core 인터럽트, F4에서 부딪힐 영속성)를 앞당겨 당긴다.
> 지금 넣으면 **재개 못 하는 승인**이 된다.

**그 예측이 틀렸다.** 이 노트는 왜 틀렸는지에 관한 것이다.

## 발견 · 우리 에이전트는 이미 재개 가능했다

노트 21(F3.1)의 발견이 이 단계의 열쇠였다 — **에이전트의 유일한 상태가 `messages` 채널**이다.
루프 카운터마저 별도 채널이 아니라 "마지막 human 이후의 툴 호출 수"로 대화에서 읽어낸다.

상태가 전부 대화 안에 있으면, **대화를 돌려주는 것이 곧 체크포인트다.** 그래서:

| | langgraph | 우리 |
|---|---|---|
| 멈춤 | `interrupt()` — 엔진이 실행을 중단하고 스냅샷을 저장 | **답 없는 `tool_use`를 남기고 run이 끝난다** |
| 저장 | checkpointer(SQLite/Postgres) | 없음 — 이력을 쥔 쪽이 호출자다 |
| 재개 | `invoke(Command(resume=...), thread_id)` | **같은 이력으로 새 run** |

새 실행 API가 하나도 없다. `stream()`·`invoke()` 그대로다. **core는 한 글자도 안 바뀌었다.**

정직하게 말하면: 재개 사이에 프로세스가 죽어도 되는 건 우리가 영속성을 가져서가 아니라
**이력을 쥔 쪽이 클라이언트**라서다. 그건 F4가 뒤집을 전제다(서버가 대화를 소유하는 순간
체크포인터가 진짜로 필요해진다). 하지만 지금 전제에서는 이게 **틀린 지름길이 아니라 맞는 결론**이다.

## 발견 · 술어 하나가 진입과 이탈을 둘 다 정한다

이 커밋의 모든 제어흐름이 함수 하나에서 나온다.

```ts
pendingToolCalls(messages)   // 마지막 AI 메시지의 toolCalls 중 답(toolCallId) 안 붙은 것
```

"답 없는 `tool_use`"는 원래 **금지된 상태**였다 — F2.3의 종료 불변식이 그걸 안 남기려고
마지막 호출에 툴을 안 줬다. 이 커밋은 그 금지된 상태를 **의미 있는 상태로 승격시킨다**:
그게 곧 "사람에게 물어볼 게 남았다"는 뜻이다.

그러자 진입과 이탈이 **같은 술어의 방향만 반대**가 된다.

```
       대기 있음                        대기 없음
START →  tools  (재개)          START →  model   (새 요청)
tools →  END    (멈춤)          tools →  model   (평소 루프)
```

진입이 `model`이면 안 되는 건 취향이 아니라 **정확성**이다. 답 없는 `tool_use`를 실은 이력을
그대로 모델에게 되보내면 Anthropic·OpenAI 양쪽 와이어 포맷 다 400이다.

## 판단 · 게이트는 실행의 변형이 아니라 실행 **앞의 결정**이다

`gatedToolNode`는 `toolNode`를 **감싼다**. 그래서 `@ariadne/tools`가 **한 글자도 안 바뀌었다** —
F3.2에서 MCP가 그랬던 것과 같은 결과이고, 이유도 같다. 툴 링의 계약(`호출 id 하나당 결과 하나`)이
이미 충분히 좁았다.

세 갈래가 전부 **이력에 무엇을 쓰느냐**로만 갈린다. 별도 채널도, 엔진 신호도, 예외도 없다.

| 결정 | 노드가 쓰는 것 | 라우터가 보는 것 | 결과 |
|---|---|---|---|
| `allow` | 툴 결과 (toolNode가) | 대기 없음 | `model` |
| `deny` | 거부 결과 메시지 | 대기 없음 | `model` |
| `ask` | **아무것도 안 쓴다** | 대기 남음 | `END` (멈춤) |

**"아무것도 안 쓴다"가 멈춤의 표현**인 게 요점이다. "채널이 유일한 공유 가변 상태"라는 불변식
아래에서, 노드가 침묵하는 것 말고 멈춤을 표현할 방법이 없다 — 그리고 그거면 충분했다.

## 판단 · `tools → model`이 정적 엣지에서 조건부로 바뀐다

게이트가 붙은 그래프에 **정적 엣지가 하나도 없다**(테스트가 이걸 못박는다). 이유는 F2.2 주석이
이미 적어둔 것이다 — **정적 엣지는 취소가 안 된다.** 제어흐름이 채널 쓰기이고 쓰기는 합집합이라,
`Command.goto: END`로도 `tools→model`을 못 막는다. 멈추려면 **애초에 안 써야** 한다.

그래서 노드 수는 그대로 둘(`model`·`tools`)이고, 바뀐 건 **두 엣지의 종류**뿐이다.
승인 게이트가 그래프에 새 노드를 안 만든다는 게 F3의 논지("agent = 특수한 그래프")의 연장이다.

## 판단 · 정책은 호출 하나가 아니라 **묶음**을 받는다

```ts
type ApprovalPolicy = (calls: readonly ToolCall[]) => Approval | Promise<Approval>
```

한 묶음은 모델의 **한 번의 결정**이다. 절반만 돌리면 나머지 `tool_use`가 답 없이 남아 이력이
깨진다(그리고 그 상태는 우리 표현에서 "멈춤"과 구별이 안 된다). 사람에게도 "이 셋을 할까요"가
"이건 되고 저건 안 되고"보다 대답하기 쉽다. 호출별 정책이 필요하면 `askFor(names)`처럼
**가장 위험한 호출이 묶음의 등급을 정하도록** 올려 붙인다.

## 판단 · 비동기 정책 하나가 두 모양을 덮는다

정책이 `Promise`를 돌려줄 수 있다는 것만으로 **사람이 서는 자리가 둘로 갈린다.**

- **터미널 앱**: 정책 안에서 `await confirm()`. `"ask"`를 아예 안 쓰므로 run이 **안 멈춘다** —
  사람이 루프 **안**에 서 있다.
- **HTTP 앱(스튜디오)**: 요청 안에서 사람을 기다릴 수 없으니 `"ask"`로 **멈추고**, 사람이 누른
  결정을 다음 요청의 정책이 돌려준다 — 사람이 루프 **사이**에 선다.

인터페이스가 하나인 게 우연이 아니다. 둘 다 "이 묶음을 돌려도 되나"라는 같은 질문이고,
다른 건 **답이 오는 데 걸리는 시간**뿐이다.

## 판단 · `deny`는 멈춤이 아니다

거부는 새 개념을 하나도 안 만든다 — **그냥 툴 결과다**(`status: "error"`). 모델이 그걸 읽고
다른 길을 찾는다. F3.2에서 MCP의 `isError`를 던지지 않고 모델에게 보여주기로 한 것과 같은 판단이고,
"모델이 고칠 수 있는 건 모델에게 말한다"는 F2.2 에러 정책의 연장이다.

## 판단 · 툴 없이 승인 정책만 주면 만들 때 던진다

`ApprovalWithoutToolsError`. 툴이 없으면 tools 노드 자체가 안 생기고 정책은 **영영 안 불린다.**
그대로 두면 "승인을 걸었다"고 믿는 에이전트가 아무것도 안 물어보고 돈다 — 승인 게이트에서
그건 가장 나쁜 종류의 조용한 오작동이다(안전 장치가 안 걸린 걸 아무도 모른다).
`ModelCannotUseToolsError`(F3.1)와 정확히 같은 판단이고, 이제 이 링의 에러 정책이 문장 하나가 된다:
**조용한 오작동을 만드는 설정은 세워둔다.**

## 검증

- `bun run --filter '@ariadne/agent' example:approval` — 네 장면. 부수효과가 배열에 남는 툴이라
  **"승인 안 했으면 안 돌았다"가 말이 아니라 관찰**로 나온다.
  1. `ask` → `step 0: model / step 1: tools`에서 끝. 지워진 파일 `[]`, 대기 1건.
  2. 같은 이력으로 `deny` → 끝까지 돌았는데 여전히 `[]`.
  3. **같은 이력**으로 `allow` → `step 0: tools`부터 시작(model을 안 부른다), `[notes.md]`.
  4. `askFor(["delete_file"])`로 `read_file` 호출 → 안 묻고 조용히 돈다.
- 테스트 +13 (agent 7 → **20**): 대기의 정의(이전 턴의 흔적은 안 센다) · 멈춤이 메시지를 하나도
  안 남긴다 · 재개 시 `[["tools"],["model"]]` 스텝 순서 · 거부의 id 짝·`status` · 비동기 정책 ·
  묶음 승격(안전한 호출도 같이 선다) · 구성 시점 검사 · **게이트 없는 그래프 모양 회귀**.
- `bun run verify` 그린: **309 pass / 4 skip / 0 fail** (core 81 · tools 28 · mcp 37 · model 97 ·
  **agent 20** · studio 46). **agent 뺀 다섯 패키지 무수정** — core도, tools도.

## 안 한 것 (정직)

- **거부 사유**를 정책이 못 싣는다(`Approval`이 문자열 유니언). 사람이 "왜 안 되는지"를 모델에게
  전할 자리가 필요해지면 그때 객체로 넓힌다.
- **호출별 결정**(하나는 승인, 하나는 거부) — 위의 묶음 판단대로 의도적으로 뺐다.
- **정책이 인자를 고쳐 승인**하는 길(claude-code의 "edit then allow") — 그러려면 이력의 `toolCalls`를
  다시 써야 하는데, 그건 "모델이 한 말을 우리가 고친다"라 별도 판단이 필요하다.
- **스튜디오 UI** — 이 커밋은 링까지다. 승인 버튼·대기 표시는 다음 커밋(S12).
- **영속성** — 재개는 여전히 "호출자가 이력을 들고 있다"에 기댄다. 서버가 대화를 소유하면
  깨진다. 그게 F4 메모리 링이다.

## 벽 → 다음

게이트가 링에는 있는데 **누를 버튼이 없다.** 스튜디오는 아직 `agentTurn`이 새 메시지만 돌려주는
규약이라, 멈춘 run을 "빈 응답"으로 볼 뿐 대기 중인 호출을 사람에게 못 보여준다. `pendingToolCalls`를
응답에 실어 승인/거부 버튼을 붙이면 F3.2 이후 처음으로 **`filesystem` 에이전트에게 쓰기 툴을
안전하게 열어줄 수 있다** — S11이 폴더 하나로 좁혔던 회피를 거둔다. 그게 S12.
