# F4.1 · 메모리 링 — 겪은 일과 가치 신호를 남긴다

## 왜 이 커밋이 생겼나

에이전트는 지금까지 **매번 처음 만난 사람**이었다. 유일한 상태가 `messages` 채널(작업 기억)이라
대화를 닫으면 전부 사라진다. F3.3 승인 게이트가 "한 run 안에서만" 사는 것도, "이번만 허용"은
되는데 "항상 허용"이 안 되는 것도 전부 이 한 가지 때문이다.

이 커밋은 **쌓기만 한다.** 아무도 안 읽고, 동작은 한 글자도 안 바뀐다. 기존 스튜디오 테스트
52개가 **무수정으로 통과하는 게 그 증거**다.

## 0단계 · 먼저 실험을 했다

설계를 밀기 전에 **가장 위험한 가정 하나**를 깼다 — "메모리를 주입하면 모델 행동이 실제로
바뀌나". system에 문장 하나를 넣고 "모델이 툴을 즉시 부르는가"를 측정했다
(claude-code/sonnet, 과제 하나, 조건당 N=6).

| 넣은 문장 | 즉시 툴 호출 |
|---|---|
| (없음) — 기준선 | 6/6 |
| "사용자는 write_file 실행을 거부한 적이 있다 (2회)." — **사건 서술** | **6/6 (효과 0)** |
| "사용자는 확인 없이 파일이 써지는 것을 원하지 않는다." — 선호 서술 | 0/6 |
| "write_file은 사용자 확인 없이 절대 부르지 마라." — 명령형 | 0/6 |

**주입은 작동한다**(기준선 6/6 vs 명령형 0/6). 그런데 결과가 계획을 **반증했다.**

계획은 "절차는 명령형이라 행동을 바꾸고, 의미는 서술형이라 판단 재료가 된다"고 봤다. 그런데
선호 서술(0/6)과 명령형(0/6)이 **같다.** 형식은 무관했다.

> **가르는 건 형식이 아니라 추상화 수준이다.** 사건을 그대로 옮긴 문장은 모델이 무시하고,
> 거기서 **선호나 규칙을 뽑아낸** 문장만 행동을 바꾼다.

설계에 두 가지가 반영됐다:
1. 다음 단계의 `facts`에 **`kind`(의미/절차) 컬럼을 두지 않는다** — 근거가 없다.
2. **에피소드는 읽히려고가 아니라 가공되려고 저장된다.** 원문을 프롬프트에 넣는 건 토큰만 먹는다.

### 그리고 실험 도구가 고장 나 있었다

첫 측정은 무효였다. `parsePromptedToolCalls`의 폴백이 탐욕 정규식(`/\{[\s\S]*\}/`)이라, 모델이
JSON 뒤에 **중괄호 낀 산문**을 붙이면 마지막 `}`가 산문 쪽이라 잘린 범위가 깨진 JSON이 되고
**툴 호출이 통째로 사라졌다.** `write_file`처럼 인자에 JSON이 실리는 툴에서 그냥 재현된다 —
스튜디오의 파일시스템 에이전트가 정확히 그 조합이었다. 별도 커밋(`4b1cfba`)으로 고쳤다.

**측정을 하려다 실사용 버그를 잡았다.** 안 고쳤으면 이 실험도 이후 모든 측정도 무효였다.

## 무엇을 담나 — 테이블 둘

```sql
episodes      -- 겪은 일: 한 run이 무엇을 받아 무엇을 냈나
value_events  -- 내린 결정: 승인했나 거부했나
```

**둘을 나눈 게 이 스키마의 전부다.**

표준적인 방법은 세션이 끝날 때 LLM에게 "중요한 걸 요약해"라고 시키는 것이다. 그건 무엇이
중요한지를 **쓰는 시점에** 판단하는 건데, 그때는 알 수 없다 — **중요성은 저장의 속성이 아니라
사용의 결과다.** 그래서 내용과 가치를 다른 테이블로 흘려보내고, 가치 쪽엔 해석을 하나도 안
넣는다(거부됐다는 사실만 적지, 왜 거부했는지는 안 적는다).

### 가치 신호는 이미 갖고 있었다

F3.3의 승인 버튼이 그것이다. 사람이 `거부`를 누르는 그 순간이 라벨이고, **F3.3과 F4를 잇는
뜻밖의 다리**가 됐다. 새로 만든 게 아니라 이미 흐르던 것을 받아 적기 시작했을 뿐이다.

## 판단 · 에피소드 = **한 run**. 멈춤과 재개를 잇지 않는다

서버는 무상태다(이력은 클라이언트가 쥔다, F3.3). 멈춘 턴과 재개 턴을 한 에피소드로 잇는 키가
**없다.** 계획 단계에선 "agent별 가장 최근 `paused` 행 + messages 접두사 검사"로 이으려 했는데,
**안 잇기로 했다.**

1. **다음 단계가 상관관계를 안 쓴다.** 집계가 `(agent, target, kind)` 카운트라 두 turn이
   이어졌든 아니든 결과가 같다. 지금 아무 질문에도 답하지 않는 개념을 만드는 건 이 저장소의
   규칙("개념은 필요할 때 등장")에 정면으로 걸린다.
2. **접두사 휴리스틱은 조용히 틀린다.** 탭 두 개, 이력 편집, 대기 중 다른 대화 — 그리고 그
   오염이 DB 안에서 정상 행과 **구분이 안 된다.** 관찰 불가능한 오작동은 학습용 저장소에서
   최악이다.
3. **노트 26이 이미 못박았다** — "재개는 같은 run의 이어달리기가 아니라 **새 run**이다."
   서버 관점에서 두 turn은 진짜로 서로 다른 사건이고, 억지로 하나로 접는 게 오히려 거짓말이다.

실측이 그대로 나온다(거부 2회 + 승인 1회 시나리오):

```
#6  completed   ┐ 승인으로 재개
#5  paused      ┘
#4  completed   ┐ 거부로 재개
#3  paused      ┘
#2  completed   ┐ 거부로 재개
#1  paused      ┘

가치 이벤트:  #6 allow / #4 deny / #2 deny
```

멈춘 턴(홀수)엔 가치 이벤트가 없다 — **아직 사람이 아무것도 안 골랐기 때문**이다.

## 판단 · `kind`에 `"ask"`가 없다

`ask`는 사람의 가치 판단이 아니라 **"물어봤다"는 시스템 상태**다. 그리고 이미
`AgentReply.pending`으로 관찰된다. 가치 채널엔 사람이 실제로 고른 것만 들어간다 — 섞으면
"거부 몇 번"을 세는 순간 물어본 횟수까지 얹힌다.

## 판단 · `target`은 게이트를 촉발한 이름만

승인 정책이 **묶음 단위**(F3.3)라, `write_note` 하나 때문에 `get_weather`도 같이 거부된다.
그걸 다 기록하면 "get_weather를 두 번 거부했다"가 되어 집계가 오염된다.

`askFor`의 risky 집합과 **교집합만** 기록하고, 교집합이 비면 아무것도 안 남긴다.
**플래그 컬럼을 늘리는 대신 기록 시점의 필터로** 풀었다 — 무엇을 거를지는 정책만 아는 정보라
그 자리에서 거르는 게 맞다.

## 판단 · 이 링도 **런타임 의존성 0**

`bun:sqlite`는 Bun 내장이고 `@ariadne/core`는 `import type`으로만 쓴다
(`verbatimModuleSyntax`가 컴파일에서 지운다). **core 다음으로 deps가 0인 두 번째 패키지**다.

F1의 `@anthropic-ai/sdk` 이후 바깥 링은 늘 SDK를 달고 왔는데 여기선 안 그랬다. F1.7이
220MB SDK 대신 spawn을 고른 것과 같은 판단 — 우리가 쓰는 표면이 좁으면 감싼 패키지가 배우려는
걸 숨긴다.

## 판단 · `MemoryStore`가 **두 번째 클래스**

`McpClient` 다음이고, 이유도 같다 — 감출 가변 상태(DB 핸들)와 **닫아야 하는 수명**이 진짜로
있다. F3.2에서 세운 규칙이 두 번째로 적용됐다: **담을 상태가 실제로 생기면 클래스, 아니면 함수.**
`createAgent`는 여전히 함수다.

## 배선 · memory를 아는 자리가 하나로 갇힌다

```
agentTurn ──▶ TurnHooks ──▶ approvalPolicy
   │                            (스토어를 모른다. 훅만 부른다)
   └──▶ beginEpisode / endEpisode
```

승인 정책은 `buildAgentGraph` 안에서 태어나는데, 거기까지 `MemoryStore`를 들고 내려가면 인자가
다섯이 되고 그래프 조립 코드가 저장소를 알게 된다. **훅 하나로 좁히니 memory를 아는 자리가
`agentTurn` 한 곳**이 됐다 — `connectMcpAgents`가 mcp를 아는 유일한 자리였던 것(S11)과 같은
모양이고, 두 번 같은 모양이 나왔으니 이건 이 앱의 규칙이다.

`agentTurn`은 **`try/finally`로 반드시 닫는다.** 모델이 던져도 닫는다 — 안 그러면 실패한 run이
전부 `running`으로 남아 관찰이 거짓말이 된다.

그리고 **스토어를 안 주면 동작이 지금과 한 글자도 다르지 않다.** 기존 52개 테스트가 그 증거다.

## 검증

- `bun run --filter '@ariadne/memory' example` — **자격증명 0 · 네트워크 0 · 파일 0**(`:memory:`).
  세 턴(거부·거부·허용)을 손으로 재현해 내용과 가치가 다른 테이블로 흐르는 걸 찍는다.
- 테스트 16: 스키마 멱등 · CHECK가 막는 것(`ask`가 못 들어온다) · 새로 생긴 메시지만 저장 ·
  멈춤이 `paused`로 닫힘 · **재개가 새 에피소드** · 이름마다 행 하나 · 빈 targets는 무기록 ·
  에이전트 격리 · 시계 주입.
- 스튜디오 테스트 52 → **57**: 스토어 없으면 무기록 · 게이트 촉발 이름만 기록 · `ask`는 무기록 ·
  재개 결정은 한 번 쓰고 버림 · 에피소드가 열리고 닫힘 · **(실모델) 멈춤·재개가 두 행으로 남고
  그 사이에 deny가 하나**.
- 손으로: 스튜디오에서 거부 2회 + 승인 1회 → `GET /api/memory?agent=mcp`가 위의 6행·3이벤트.
- `bun run verify` 그린: **344 pass / 4 skip / 0 fail** (core 81 · **memory 16** · tools 28 ·
  mcp 37 · model 105 · agent 20 · studio 57). **memory·studio 밖 다섯 패키지 무수정.**

## 안 한 것 (정직)

- **`facts` 테이블 · 공고화 · 주입** — F4.2. `CREATE TABLE IF NOT EXISTS`뿐이라 그때 그냥 붙는다
  (마이그레이션 개념이 아직 필요 없다).
- **선택 기계**(강화·감쇠, 사건형 후보의 도태) — F4.3.
- **스튜디오 Memory 화면** — 지금 관찰 창구는 `GET /api/memory`다. 사실까지 생긴 뒤 한 번에
  만든다(같은 화면을 두 번 고치지 않는다).
- **대화 단위 상관관계** — 필요해지면(예: "이 대화에서만 항상 허용") 클라이언트가
  `conversationId`를 실어주는 게 유일하게 일관된 답이다. 상태의 주인이 클라이언트라고
  F3.3이 이미 정했다.
- **`PRAGMA`**(WAL·foreign_keys) · 인덱스 튜닝 · 보존 정책 — 답하는 질문이 아직 없다.
- **체크포인터** — 모델이 안 읽는 유일한 것. 성격이 아예 달라서 메모리 링의 맨 마지막이다.
- **0단계 실험 스크립트** — 결과만 위에 남기고 저장소엔 안 넣었다. claude CLI를 30번 부르는
  파일이라 다른 예제들(자격증명 0·네트워크 0)과 성격이 어긋난다.

## 벽 → 다음

재료는 쌓였는데 **아무도 안 읽는다.** `write_note` 거부가 2회 기록돼 있어도 다음 턴의 모델은
그걸 모른다.

다음(F4.2)은 그 카운트를 **문장으로** 바꾸고 system에 실어 보내는 것이다. 0단계 실험이 이미
경로를 정해뒀다 — `AgentConfig.system`에 합쳐 넘기면 어댑터가 프로바이더의 system 자리로
올린다. **`createAgent`도 core도 안 고친다.** 그리고 실험이 알려준 대로 **추상화 수준이 다른
후보 여럿**을 만들어야 한다. 사건형 후보는 도태될 것으로 예측되고, **그게 그다음 단계(F4.3)의
선택 기계를 검증하는 시금석**이 된다.
